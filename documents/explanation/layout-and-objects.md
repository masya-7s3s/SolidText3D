# レイアウト・アウトライン・文字単位オブジェクトの仕組み

このページでは、見た目の配置がどう決まるか、アウトラインがどう管理されるか、PerCharacter がどう動くかを説明します。

## 横書きと縦書きで、効く設定が少し違う

### 横書き

横書きでは、文字は通常どおり左から右へ並びます。  
各行の X 位置は Horizontal Anchor に合わせて調整されます。

Vertical Anchor と Depth Anchor は、メッシュ全体の bounds を使って最後に反映されます。

### 縦書き

縦書きでは、文字は上から下へ進み、列は右から左へ増えます。  
Vertical Anchor は列ごとに調整され、Horizontal Anchor と Depth Anchor はメッシュ全体のオフセットとして扱われます。

この違いのため、横書きと縦書きでは「どのアンカーがどの段階で効くか」が完全には同じではありません。

## 縦書きの句読点は少し右上に寄る

日本語の「、」「。」は、縦書き時に通常文字と同じ中央配置ではなく、セルの右上寄りへ置かれます。  
これは縦組みらしい見え方を保つための実装です。

一方、ASCII を RotateAsciiInVertical で回転させた場合は、この句読点補正とは別処理になります。

## MaxHeight は効くが、MaxWidth はまだ実用設定ではない

縦書きでは MaxHeight による列折り返しが実装されています。  
高さを超えそうになった時点で次の列へ進みます。

一方で、横書きの MaxWidth は現在のレイアウト処理では使われていません。  
そのため、横書きの改行は現状では明示的な改行文字で制御するのが前提です。

## アウトラインは別の子オブジェクト

アウトラインは本体メッシュに混ぜ込まれず、__OutlineMesh__ という子オブジェクトで別管理されます。  
これには次の利点があります。

- 本体と別マテリアルを使いやすい
- 本体の再生成とアウトラインの再生成を分けて扱いやすい
- OutlineEnabled のオン・オフでライフサイクルを明確にできる

挙動は次のようになっています。

- OutlineEnabled = false で子オブジェクトを破棄
- OutlineEnabled = true で子オブジェクトを生成または再利用
- OutlineOffset = 0 では子オブジェクトを残し、メッシュだけ空にする

## PerCharacter はプール方式

ObjectMode を PerCharacter にすると、可視文字ごとに子オブジェクトを持ちます。  
毎回すべてを作り直すのではなく、既存オブジェクトをなるべく再利用するプール方式です。

基本動作は次の通りです。

- 文字数が増えたときだけ不足分を新規作成
- 余った子オブジェクトは削除ではなく非アクティブ化
- SingleObject に戻したときや空文字列ではまとめて破棄

この仕組みにより、文字単位アニメーションや演出はやりやすくなります。  
ただし、SingleObject よりオブジェクト数が増えるため、常にこちらが有利というわけではありません。

## SingleObject と PerCharacter の見た目を揃える仕組み

PerCharacter でも SingleObject と同じ位置に見えるよう、内部では一度全体メッシュ相当の bounds からアンカーオフセットを計算し、それを各文字へ反映しています。  
そのため、ObjectMode を切り替えても大きく位置がずれにくい作りになっています。
