# Feature Specification: テキストアウトライン生成

**Feature Branch**: `003-text-outline`  
**Created**: 2026-04-22  
**Status**: Draft  
**Input**: User description: "文字本体に対して外周方向へオフセットした形状のアウトラインを生成する"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - アウトライン基本表示 (Priority: P1)

ユーザーが 3D テキストコンポーネントのインスペクターでアウトラインを有効化し、オフセット量を指定すると、文字の外側にアウトライン形状が生成されシーンに表示される。

**Why this priority**: アウトライン機能の根幹となる形状生成であり、他のすべての機能の土台となる。

**Independent Test**: インスペクターでアウトラインを有効にし、オフセット量を設定した状態でシーンを再生すると、文字の外側にアウトライン形状が表示されることを確認できる。

**Acceptance Scenarios**:

1. **Given** アウトラインが無効の状態, **When** インスペクターでアウトラインを有効にしオフセット量を設定する, **Then** 文字の外周にオフセット量に応じた輪郭形状が表示される
2. **Given** アウトラインが有効の状態, **When** オフセット量を変更する, **Then** アウトライン形状がリアルタイムに更新される
3. **Given** オフセット量が非常に大きい値, **When** アウトラインが生成される, **Then** オフセット処理によって生じる不自然な内側の穴が自動的に削除され、アウトライン形状が連続した単一の面として表示される

---

### User Story 2 - アウトライン表示モード切り替え (Priority: P2)

ユーザーがインスペクターでドーナツモードと裏面埋めモードを切り替えると、アウトラインの裏面形状が変化する。正面からの見た目は両モードで変わらない。

**Why this priority**: 2モードは独立した視覚表現を提供し、それぞれ異なるユースケースを満たす。

**Independent Test**: ドーナツモードと裏面埋めモードをそれぞれ選択し、オブジェクトを回転させて裏面の見た目が仕様通りに変化することを確認できる。

**Acceptance Scenarios**:

1. **Given** ドーナツモードが選択されている, **When** アウトラインを背面から観察する, **Then** 中央に文字本体が透けて見えるリング状の形状になっている
2. **Given** 裏面埋めモードが選択されている, **When** アウトラインを背面から観察する, **Then** アウトライン内部が塗りつぶされた太字のような形状になっており、中央のくぼみに文字本体がはめ込まれた構造になっている
3. **Given** いずれかのモードが選択されている, **When** 正面からアウトラインを観察する, **Then** 両モードで表面の形状と基準位置が一致している
4. **Given** 裏面埋めモードが選択されている, **When** 文字本体の厚さ > アウトラインの厚さ の場合, **Then** アウトラインの裏面は文字本体の裏面位置に合わせて生成され、面の重なりを回避する
5. **Given** 裏面埋めモードが選択されている, **When** アウトラインの厚さ ≥ 文字本体の厚さ の場合, **Then** アウトラインの裏面はアウトラインの厚さに応じた位置に生成され、面の重なりを回避する

---

### User Story 3 - アウトラインの生成/削除切り替え (Priority: P2)

ユーザーがインスペクターでアウトラインのトグルをオフにすると、アウトライン用子 GameObject が破棄されメッシュが削除される。再度オンにすると子 GameObject が新たに生成されメッシュが構築される。

**Why this priority**: 生成/削除の切り替えは開発・制作ワークフローで頻繁に使用される。

**Independent Test**: インスペクターでトグルをオフにするとシーンビューからアウトラインの子 GameObject が消え、再度オンにすると新たに生成されることを確認できる。

**Acceptance Scenarios**:

1. **Given** アウトラインが有効の状態, **When** トグルをオフにする, **Then** アウトライン用子 GameObject が破棄され、文字本体のみが表示される
2. **Given** アウトラインが削除された状態, **When** トグルをオンにする, **Then** アウトライン用子 GameObject が新たに生成され、メッシュが表示される
3. **Given** アウトラインが削除された状態, **When** オフセット量やモードを変更する, **Then** 設定値は SerializeField に保持され、再生成時に反映される

---

### User Story 4 - アウトラインの厚さとマテリアル設定 (Priority: P2)

ユーザーが文字本体とは独立して、アウトラインの Z 軸方向の厚さとマテリアルを設定できる。

**Why this priority**: アウトラインに独立したビジュアル設定を与えることで、デザインの自由度が高まる。

**Independent Test**: アウトラインの厚さを文字本体と異なる値に設定し、別のマテリアルを割り当てると、アウトラインが独自の外観で表示されることを確認できる。

**Acceptance Scenarios**:

1. **Given** アウトラインが有効の状態, **When** 文字本体と異なる厚さをアウトラインに設定する, **Then** アウトラインが指定した厚さで表示される
2. **Given** アウトラインが有効の状態, **When** アウトラインに専用マテリアルを割り当てる, **Then** アウトラインが割り当てたマテリアルで描画される（文字本体のマテリアルとは独立）
3. **Given** アウトラインが有効の状態, **When** 文字本体のマテリアルを変更する, **Then** アウトラインのマテリアルは変化しない

---

### Edge Cases

- オフセット量が非常に大きく、文字形状内の穴（例: 「O」の中空部分）がオフセット外形と接触・重なる場合、穴は自動的に削除され単一の連続する面として扱われる
- アウトラインの厚さが 0 の場合、アウトラインは表面ポリゴンのみ（側面・裏面なし）で生成される。警告は表示しない（入力として有効な値とみなす）
- 文字本体とアウトラインの裏面が同一 Z 位置になる場合の Zファイティング防止については FR-009 を参照（`Z_FIGHT_EPSILON = 0.0001f` の微小オフセットを適用）
- 裏面埋めモードで厚さが等しい場合、文字本体の裏面を基準としアウトライン裏面を微小量後方にずらす

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは、フォントのグリフパスを外側へユーザー指定量オフセットした輪郭形状を生成しなければならない
- **FR-002**: オフセット処理後に生じる不自然な内側の穴（消えるべき空洞）を検出し、単一の連続した面として自動的にマージしなければならない。穴の判定基準: Clipper2 の `Clipper.Area()` による符号付き面積計算において CW 方向（`Area() < 0`）と判定されたポリゴンを穴とみなし除去する
- **FR-003**: ユーザーは、アウトラインの Z 軸方向の厚さを文字本体と独立して設定できなければならない
- **FR-004**: ユーザーは、アウトラインのマテリアルを文字本体と独立して割り当てられなければならない。なお、`OutlineMaterial` が null の場合は文字本体 `MeshRenderer.sharedMaterial` へ自動フォールバックしなければならない
- **FR-005**: ユーザーは、アウトラインの生成/削除をトグルで制御できなければならない。オフにすると子 GameObject が破棄され、オンにすると新たに生成される
- **FR-006**: システムは**ドーナツモード**をサポートしなければならない。このモードでは、アウトラインはリング状の形状となり、背面から見たとき中央に文字本体が透けて見える
- **FR-007**: システムは**裏面埋めモード**をサポートしなければならない。このモードでは、アウトライン内部が裏面で塗りつぶされ、外側へオフセットした形状に文字本体のくぼみが設けられた構造になる
- **FR-008**: 裏面埋めモードにおいて、アウトラインの裏面位置は「文字本体の裏面位置」と「アウトライン厚さによる裏面位置」のうち、より後方の値を採用しなければならない
- **FR-009**: 裏面埋めモードにおいて、アウトラインと文字本体の面が同一位置に重ならないよう、裏面位置を調整しなければならない
- **FR-010**: アウトラインの表面（Z+ 側の面）の基準位置は、ドーナツモードと裏面埋めモードで同一でなければならない（モード切り替えで変化してはならない）
- **FR-011**: ユーザーはアウトラインのオフセット量を Unity 単位の数値で指定できなければならない（インスペクター入力・API ともに Unity 単位。内部演算は em 空間で実施）

### Key Entities

- **OutlineSettings**: アウトラインの全設定を保持するデータ構造。有効フラグ、オフセット量、Z 軸厚さ、マテリアル、表示モードを含む
- **OutlineMesh**: オフセットされたグリフパスから生成されたメッシュ。表面・側面・（裏面埋めモード時）裏面を含む
- **OutlineDisplayMode**: ドーナツモードまたは裏面埋めモードを表す列挙値
- **OffsetContour**: グリフの輪郭パスをオフセット演算した後のポリゴン輪郭データ。穴除去後の状態を保持する

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: アウトライン形状が文字本体と視覚的に独立して認識でき、指定したオフセット量に比例した外周拡張が確認できる（自動テスト基準: オフセット量を 2 倍にした場合、結果輪郭の外周長増加率の誤差が ±15% 以内であること）
- **SC-002**: 任意の日本語・英語グリフに対してオフセット処理を行った結果、不自然な穴が残らず単一の連続した面として生成される
- **SC-003**: ドーナツモードと裏面埋めモードで、正面から見た表面形状と基準位置が完全に一致する（目視で差異がない）
- **SC-004**: 裏面埋めモードにおいて、あらゆる厚さの組み合わせで面の重なり（Zファイティング）が発生しない
- **SC-005**: アウトラインの生成/削除（トグル）、厚さ、マテリアル、オフセット量の変更が、インスペクターからそれぞれ独立して適用できる

## Assumptions

- アウトラインのオフセット演算は、ランタイムでの動的生成ではなく、パラメータ変更時に Editor 上でメッシュを再生成するアプローチを採用する。再生成は `OnValidate` でダーティフラグを立て、`LateUpdate` 内で一度だけ実行する（既存コンポーネントと同一パターン）
- オフセット演算には **Clipper2**（純 C# ポリゴンオフセットライブラリ）を新規依存として追加する。Clipper2 は穴除去（FR-002）を組み込みでサポートし、`BezierSubdivider` で事前にポリゴン化したパスデータを入力として、`LibTessDotNet` による三角分割と連携して使用する。演算はフォント em 空間で実施し（整数化スケール係数、例: ×1000 を適用）、最終段階で Unity 単位に変換する
- アウトラインのオフセット量の下限は 0（アウトラインなし相当）とし、負値（内側オフセット）は本機能のスコープ外とする。オフセット量および厚さの上限は設けず、0 以上の任意の正値を受け付ける（バリデーションなし）
- 裏面埋めモードの「くぼみ」は文字本体形状と同一であり、別途形状定義は不要
- アウトラインは文字本体 GameObject の**子 GameObject**（専用 MeshFilter + MeshRenderer 付き）として管理される。`Enabled` を false にすると子 GameObject を `Destroy`（Editor では `DestroyImmediate`）し、true にすると新規生成してメッシュを構築する。これによりマテリアルの完全独立を実現する
- 文字本体の表面（Z+ 側）を基準位置 Z=0 として設計する（両モードで共通）
- 厚さが 0 の場合、`OutlineMeshBuilder` は表面ポリゴンのみを生成し、側面および裏面は省略する。バリデーションエラーや警告は発生させない（FR-003 の「0 以上の任意の正値を許可」に準拠）

- Q: アウトラインメッシュの再生成タイミングはいつですか？ → A: `OnValidate` でダーティフラグを立て `LateUpdate` 内で一度だけ再生成（既存パターンと統一）
- Q: Clipper2 のオフセット演算の座標空間はどこで行いますか？ → A: フォント em 空間で演算（整数化スケール係数適用）し最終段階で Unity 単位に変換
