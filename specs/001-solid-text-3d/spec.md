# 機能仕様書: Solid Text 3D

**フィーチャーブランチ**: `001-solid-text-3d`  
**作成日**: 2026年4月17日  
**ステータス**: Draft  
**概要**: Unityのエディタ拡張およびランタイム拡張「Solid Text 3D」——テキストを3Dメッシュとして生成し、ゲームオブジェクトとして扱えるようにする

---

## ユーザーシナリオとテスト *(必須)*

### ユーザーストーリー 1 — エディタでの静的3Dテキスト生成 (優先度: P1)

開発者はUnityエディタ上でフォント・テキスト・押し出し深さ・アウトライン幅を設定し、静的な3Dメッシュゲームオブジェクトをシーンに配置する。
UIキャンバスではなくWorld Space上の3Dメッシュとして機能し、物理演算やシェーダーの適用が可能な状態になる。

**この優先度である理由**: ライブラリの根幹機能であり、これ単体でMVPとして成立する。ランタイム機能はこの基盤の上に構築される。

**独立テスト**: エディタのInspectorでパラメータを設定し、生成された3Dメッシュをシーンビューおよびゲームビューで目視確認できる。

**受け入れシナリオ**:

1. **Given** 新規シーンに空のゲームオブジェクトがある状態で、**When** SolidText3Dコンポーネントをアタッチしフォント・テキスト・押し出し深さを指定したとき、**Then** 指定テキストが3Dメッシュとしてシーンビューに表示される
2. **Given** SolidText3Dコンポーネントが設定済みの状態で、**When** テキスト文字列を変更したとき、**Then** エディタのInspectorでの変更がシーンビューに即座に反映される
3. **Given** 押し出し深さを0より大きい値に設定した状態で、**When** ゲームオブジェクトをシーン内で回転させたとき、**Then** 文字の奥行き（厚み）が正しく立体的に見える
4. **Given** アウトライン幅を0より大きい値に設定した状態で、**When** メッシュが生成されたとき、**Then** 各文字の輪郭に指定幅のアウトラインジオメトリが生成されている

---

### ユーザーストーリー 2 — ランタイムでの動的テキスト変更 (優先度: P2)

開発者はスクリプトからテキスト内容を実行時に変更する（スコア、プレイヤー名、カウントダウンなど）。
変更後、3Dメッシュが新しいテキストを反映した形に自動再生成される。

**この優先度である理由**: 静的テキストだけでは動的なゲームコンテンツに対応できないため、P2として必須。

**独立テスト**: `SolidText3D.Text = "新しい文字列"` をスクリプトから呼び出し、次フレームでメッシュが更新されることを確認できる。

**受け入れシナリオ**:

1. **Given** SolidText3Dコンポーネントがアタッチされたゲームオブジェクトが実行中のシーンに存在するとき、**When** スクリプトからテキストプロパティを変更したとき、**Then** 変更後の文字列に対応した3Dメッシュが次フレームまでに生成される
2. **Given** テキストが頻繁に変更されるシナリオ（毎フレーム更新など）において、**When** 連続してテキストを変更したとき、**Then** フレームレートが著しく低下せずゲームが動作し続ける
3. **Given** ランタイムでテキストを空文字列に設定したとき、**When** テキストプロパティが空になったとき、**Then** メッシュが非表示になるかゼロポリゴン状態になりエラーが発生しない

---

### ユーザーストーリー 3 — CJKおよび多言語文字への対応 (優先度: P2)

開発者はCJK（中国語・日本語・韓国語）文字を含むテキストを3Dメッシュとして生成できる。
日本語や中国語のゲームタイトル・キャラクター名・UIテキストを立体文字として表現できる。

**この優先度である理由**: 本拡張はCJKサポートを明示的な要件としており、グローバルなゲーム開発で必須の機能。

**独立テスト**: 日本語・中国語・韓国語の文字を含むフォントを使用してテキストを設定し、正しく3Dメッシュが生成されることを確認できる。

**受け入れシナリオ**:

1. **Given** CJK文字を含むTTF/OTFフォントが指定された状態で、**When** 日本語テキスト（例：「立体文字」）をSolidText3Dに設定したとき、**Then** 各漢字・仮名が正しく3Dメッシュとして生成される
2. **Given** 混在テキスト（ラテン文字＋CJK文字）を設定したとき、**When** メッシュを生成したとき、**Then** すべての文字が途切れなく配置されたメッシュが生成される
3. **Given** フォントに含まれない文字（フォントに未収録のグリフ）を指定したとき、**When** メッシュを生成しようとしたとき、**Then** エラーで停止せず、フォールバック表示または空のグリフとして処理される

---

### ユーザーストーリー 4 — フォント設定とカスタムフォントの使用 (優先度: P3)

開発者は自分が用意したTTFまたはOTFフォントをUnityプロジェクトにインポートし、SolidText3Dに割り当てて使用できる。

**この優先度である理由**: フォントの自由な選択は品質に影響するが、デフォルトフォントがあれば基本動作は可能なためP3。

**独立テスト**: Unityのプロジェクトにカスタムフォントファイルをインポートし、SolidText3DのフォントフィールドにドラッグアンドドロップしてメッシュをUnicode文字含め正しく生成できることを確認する。

**受け入れシナリオ**:

1. **Given** TTFフォントがProjectウィンドウにインポートされている状態で、**When** SolidText3DのInspectorでフォントフィールドにそのフォントをアサインしたとき、**Then** そのフォントのグリフで3Dメッシュが生成される
2. **Given** フォントが未指定の状態で、**When** コンポーネントを使用したとき、**Then** デフォルトフォント（ビルトイン）でメッシュが生成されエラーにならない

---

### エッジケース

- フォントファイルが削除またはプロジェクトから除外された場合、コンポーネントはデフォルトフォントにフォールバックし、Unityコンソールに `Warning` を出力する（エラーで停止しない）
- テキストが非常に長い（100文字超）場合のメッシュ生成時間は **ベストエフォート扱いとし v1 保証対象外** とする（SC-001 の保証範囲は 50 文字以内）

- ランタイムでフォント自体を変更した場合、メッシュは正しく再生成されるか？

## 要件 *(必須)*

### 機能要件

- **FR-001**: システムはTTFおよびOTF形式のフォントファイルをフォントソースとして使用できなければならない
- **FR-002**: 開発者はInspectorおよびスクリプトAPIからテキスト文字列を設定できなければならない
- **FR-003**: 開発者は文字の押し出し深さ（奥行き）を数値パラメータとして設定できなければならない（0以上の任意の値）
- **FR-004**: 開発者はアウトライン幅を数値パラメータとして設定できなければならない（0以上の任意の値、0はアウトラインなしを意味する）
- **FR-005**: システムはテキスト・フォント・押し出し深さ・アウトライン幅のいずれかが変更された際に3Dメッシュを自動的に再生成しなければならない
- **FR-006**: 生成される3DテキストはユニティのゲームオブジェクトにアタッチされたMeshFilterおよびMeshRendererとして機能しなければならない（UIキャンバス要素ではない）
- **FR-007**: ランタイム中にスクリプトAPIを通じてテキストを動的に変更でき、次フレームまでにメッシュが更新されなければならない。内部実装はダーティフラグを使用し、同一フレーム内の複数プロパティ変更を `LateUpdate` で1回のメッシュ再生成に集約する
- **FR-008**: システムはCJK（漢字・ひらがな・カタカナ・ハングル）を含む任意のUnicode文字をサポートしなければならない
- **FR-009**: フォントが未指定またはフォントアセットが削除された場合、システムはデフォルトフォントにフォールバックしエラーを発生させてはならない。Unityコンソールに `Warning` レベルのログを出力する
- **FR-010**: フォントに収録されていないグリフが指定された場合、システムはエラーで停止せず代替処理（空グリフまたはスキップ）を行わなければならない
- **FR-011**: エディタのInspectorから全パラメータにアクセスでき、リアルタイムプレビューをサポートしなければならない。プレビューのトリガーは `OnValidate` コールバックでダーティフラグを立て、`EditorApplication.QueuePlayerLoopUpdate()` を呼び出してシーンビューの再描画をトリガーする方式とする
- **FR-012**: スクリプトAPIは少なくとも `Text`、`Font`、`ExtrusionDepth`、`OutlineWidth` プロパティを公開しなければならない
- **FR-013**: 開発者は文字間隔（LetterSpacing）を数値パラメータ（em単位）として設定できなければならない（デフォルト 0.0、0以上の任意の値）
- **FR-014**: 開発者は行間（LineSpacing）を数値パラメータ（em倍率）として設定できなければならない（デフォルト 1.2、0より大きい任意の値）

### キーエンティティ

- **SolidText3D コンポーネント**: テキスト文字列、フォント参照、押し出し深さ、アウトライン幅、文字間隔、行間などのメッシュ生成パラメータを保持するMonoBehaviourコンポーネント
- **フォントアセット**: UnityプロジェクトにインポートされたTTF/OTFフォントファイルへの参照
- **生成メッシュ**: 各文字のアウトライン（グリフ輪郭）を元に押し出し処理で生成される3DメッシュデータをMeshFilterに格納したもの
- **グリフデータ**: フォントから取得した各文字のベジェ曲線・輪郭情報（ポリゴン三角分割の元となるデータ）

## 成功基準 *(必須)*

### 計測可能なアウトカム

- **SC-001**: 開発者がエディタでパラメータを変更してから3Dメッシュのシーンビュー更新が完了するまで、通常使用（50文字以内）で2秒以内に収まること
- **SC-002**: CJKを含む任意のUnicode文字がフォントに含まれている限り、正しく3Dメッシュとして生成され、文字の欠損・崩れが発生しないこと
- **SC-003**: ランタイムでのテキスト変更が、50文字以内のテキストにおいて1フレーム遅延以内でメッシュ更新として反映されること
- **SC-004**: 同一シーン内に20個のSolidText3Dオブジェクト（各50文字以内）が存在しても、PC/Consoleの標準フレームレート（60fps）を維持できること（50個以上の同時使用はベストエフォートとし、v1保証対象外とする）
- **SC-005**: TTF/OTFフォントを正しくインポートすれば、追加のコード記述なしにInspectorのみでフォントを切り替えられること
- **SC-006**: エディタ拡張を導入したプロジェクトが既存のシーンやアセットと競合せずビルドを通過できること

## 前提条件・想定事項

- 対象UnityバージョンはUnity 6以降とする（Unity LTSバージョンを主軸とする）
- フォントのグリフデータはTTF/OTFのベクター輪郭として取得可能であることを前提とする
- ランタイムのメッシュ再生成はメインスレッドで行う（マルチスレッド対応はv1スコープ外）
- 文字のアニメーション（個別文字のトランスフォーム変化など）はv1スコープ外とする
- アウトラインの色やマテリアル割り当ては、Unityの標準Rendererコンポーネントを通じて行う想定（本コンポーネントはマテリアルを管理しない）
- SDF（Signed Distance Field）フォントではなく、ベクター輪郭に基づくポリゴンメッシュ生成を前提とする
- モバイルプラットフォーム（iOS/Android）は **v1スコープ外** とする。対象プラットフォームはPC/Consoleのみ
- フォントの著作権は開発者が管理するものとし、本拡張はフォントライセンスの管理を行わない
- グリフ輪郭データの取得には **SixLabors.Fonts**（純粋 C#、MIT）を使用する。`IGlyphRenderer` コールバック API 経由でベジェ輪郭を取得することで、グリフ精度とCJK対応の柔軟性を確保する
- ランタイムビルドにおけるカスタムフォント（TTF/OTF）のバイトデータ取得は **v1スコープ外** とする。フォントバイトの読み込みはエディタ環境（`AssetDatabase` 経由）でのみサポートし、ランタイムビルドではデフォルト埋め込みフォントで動作する
- デフォルト埋め込みフォントとして **Noto Sans JP Regular**（Google、SIL Open Font License 1.1）を採用する。`Runtime/Plugins/Fonts/NotoSansJP-Regular.ttf` に配置し、`GlyphMeshBuilder` の `#else` ブロックからバイト配列として参照する。日本語（ひらがな・カタカナ・漢字）・Latin を含む幅広い Unicode をカバーし、OFL 1.1 は Asset Store 配布および商用利用に適合する。ライセンス全文は `Third Party Notices.md` に記載する（取得元: <https://fonts.google.com/noto/specimen/Noto+Sans+JP>）

## Clarifications

### Session 2026-04-17

- Q: グリフ輪郭取得にどのアプローチを使用するか？ → A: SixLabors.Fonts（純粋 C#、MIT）の `IGlyphRenderer` コールバック API を使用
- Q: ランタイムでの高頻度テキスト更新時のスロットリング戦略は？ → A: ダーティフラグを立て、LateUpdateで1フレーム遅延して再生成（フレーム内の複数変更を集約）
- Q: エディタ上のリアルタイムプレビューのトリガー方法は？ → A: `OnValidate` でダーティフラグを立て、`SolidText3DInspector` の `ApplyModifiedProperties()` 後に `EditorApplication.QueuePlayerLoopUpdate()` を呼び出してシーンビューを再描画する（FR-011 準拠）
- Q: モバイルプラットフォームのサポート方針は？ → A: v1スコープ外として廃止。対象はPC/Consoleのみ
- Q: フォント削除時のエラー処理ポリシーは？ → A: デフォルトフォントにフォールバックし、コンソールに `Warning` を出力
